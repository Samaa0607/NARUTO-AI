## 1. الملف ده بيعمل إيه؟

`features.py` بياخد الـ landmarks الخام بتاعة الإيدين (لحد 2 إيد × 21 نقطة) ويحوّلها لـ **vector ثابت الطول فيه 206 رقم**، مصمم بحيث يوصف **شكل** الإيد (الصوابع مفرودة ولا مثنية، قريبة من بعض ولا لأ) ومايتأثرش بحاجات مالهاش علاقة بالـ gesture (مكان الإيد في الصورة، بُعدها عن الكاميرا).

مكانه في السلسلة: camera → hands → **features** → classifier → controller → effects → screen.

أهم نقطة في التصميم (مكتوبة في الـ docstring): **نفس الدالة بالظبط** بتُستخدم في التدريب (`train.py`) وفي التشغيل الحي (`main.py`)، فالموديل دايمًا بيشوف features محسوبة بنفس الطريقة.

## 2. الكود سطر بسطر

### الـ docstring والـ import والنسخة

```python

The same function is used by training and by the live app, so the model
always sees features computed exactly the same way.
"""

import numpy as np

FEATURE_VERSION = 1
```

- الـ docstring: "حوّل الـ landmarks لـ vector ثابت الطول. نفس الدالة بتُستخدم في التدريب وفي التطبيق".
- `numpy`: المكتبة الوحيدة اللي محتاجينها؛ كل الحسابات عمليات على arrays.
- `FEATURE_VERSION = 1`: رقم نسخة لطريقة حساب الـ features. بيتحفظ مع الموديل المتدرب، ولو حد غيّر طريقة الحساب لازم يزوّد الرقم ده (هنشرح ليه في "مفاهيم مهمة").

### أطراف الصوابع والمفاصل

```python
TIPS = [4, 8, 12, 16, 20]
# (a, b, c) triplets: the angle is measured at joint b
ANGLE_TRIPLETS = [
    (0, 1, 2), (1, 2, 3), (2, 3, 4),          # thumb
    (0, 5, 6), (5, 6, 7), (6, 7, 8),          # index
    (0, 9, 10), (9, 10, 11), (10, 11, 12),    # middle
    (0, 13, 14), (13, 14, 15), (14, 15, 16),  # ring
    (0, 17, 18), (17, 18, 19), (18, 19, 20),  # pinky
]
```

- `TIPS`: أرقام أطراف الـ 5 صوابع (إبهام، سبابة، وسطى، بنصر، خنصر).
- `ANGLE_TRIPLETS`: كل tuple فيه 3 نقط `(a, b, c)`، والزاوية بتتقاس **عند النقطة b** (زي ما التعليق بيقول). يعني الزاوية بين الخط `b→a` والخط `b→c`.
- لكل صباع 3 زوايا (مفصل القاعدة، المفصل الأوسط، المفصل الأخير). أول triplet في كل صباع بيبدأ بالرسغ `0` عشان يقيس انثناء الصباع بالنسبة للكف.
- 5 صوابع × 3 = **15 زاوية**.

### أزواج أطراف الصوابع

```python
TIP_PAIRS = [(i, j) for i in range(5) for j in range(i + 1, 5)]   # 10 pairs
```

- list comprehension بيطلع كل الأزواج المختلفة من 5 صوابع من غير تكرار: `j` بيبدأ من `i + 1` فمش هيطلع `(1, 0)` بعد `(0, 1)` ولا `(2, 2)`.
- النتيجة: `[(0,1), (0,2), (0,3), (0,4), (1,2), (1,3), (1,4), (2,3), (2,4), (3,4)]` = 10 أزواج.
- الأرقام هنا 0..4 هي **ترتيب في `TIPS`** مش أرقام landmarks؛ يعني `(0, 1)` = إبهام مع سبابة.

### أحجام الـ vector

```python
PER_HAND_SIZE = 1 + 63 + 15 + 10      # present flag + coords + angles + tip distances
INTER_HAND_SIZE = 1 + 2 + 25          # both flag + wrist offset + 5x5 tip distances
FEATURE_SIZE = 2 * PER_HAND_SIZE + INTER_HAND_SIZE
```

- `PER_HAND_SIZE = 89`: flag "الإيد موجودة" (1) + 21 نقطة × 3 إحداثيات (63) + 15 زاوية + 10 مسافات.
- `INTER_HAND_SIZE = 28`: flag "الإيدين موجودين" (1) + فرق مكان الرسغين x,y (2) + مسافات كل طرف في إيد مع كل طرف في التانية 5×5 (25).
- `FEATURE_SIZE = 2 × 89 + 28 = 206`.
- كاتبين الأرقام كجمع (`1 + 63 + ...`) مش `89` على طول، عشان أي حد يقرا يفهم الرقم جاي منين، ولو ضفنا feature نعدّل جزء واحد.

### تحويل `Hand` objects للشكل الخام: `hands_to_arrays`

```python
def hands_to_arrays(hands):
    """List[Hand] -> (image_lm (2,21,3), world_lm (2,21,3), present (2,)) — the raw format we store."""
    image_lm = np.zeros((2, 21, 3), np.float32)
    world_lm = np.zeros((2, 21, 3), np.float32)
    present = np.zeros(2, np.float32)
```

- الـ docstring بيوضح المدخل والمخرج: list من `Hand` → 3 arrays، ودي "الصيغة الخام اللي بنخزنها" في ملفات الداتا.
- `image_lm`: مكان لإيدين × 21 نقطة × 3 (normalized). بنبدأ بأصفار، فلو إيد مش موجودة هتفضل أصفار.
- `world_lm`: نفس الشكل للـ world landmarks (بالمتر).
- `present`: رقمين، `1.0` لو الـ slot فيه إيد و `0.0` لو فاضي.
- `np.float32`: نفس النوع اللي `hands.py` بيستخدمه، وحجمه نص `float64` في الملفات.

```python
    for slot, hand in enumerate(hands[:2]):
        image_lm[slot] = hand.landmarks
        world_lm[slot] = hand.world
        present[slot] = 1.0
    return image_lm, world_lm, present
```

- `hands[:2]`: أول إيدين بس (احتياطي، حتى لو حد غيّر `MAX_HANDS`).
- `enumerate`: بيدّينا رقم الـ slot (0 أو 1) والإيد.
- بما إن `HandTracker.detect` رتّب الإيدين بالـ x، فـ slot 0 = الإيد اللي على الشمال (أو الإيد الوحيدة لو فيه واحدة بس).
- بنملا الـ slot وبنعلّم إنه موجود، وبنرجّع الـ 3 arrays.

### features الإيد الواحدة: التطبيع (normalization)

```python
def _hand_features(world):
    rel = world - world[0]                                  # wrist becomes the origin
    scale = np.linalg.norm(rel[9]) + 1e-6                   # wrist -> middle knuckle
    rel = rel / scale                                       # same size for near/far hands
```

- المدخل `world`: array `(21, 3)` لإيد واحدة بالمتر.
- `rel = world - world[0]`: بنطرح مكان الرسغ من كل النقط (NumPy broadcasting: `(21,3) - (3,)`). النتيجة: الرسغ بقى `(0,0,0)` وكل نقطة بقت "مكانها بالنسبة للرسغ".
- `scale = np.linalg.norm(rel[9]) + 1e-6`: طول المسافة من الرسغ لقاعدة الوسطى (نقطة 9) = "حجم الكف". الـ `1e-6` رقم صغير جدًا بيمنع القسمة على صفر لو حصل حاجة غريبة.
- `rel = rel / scale`: بنقسم كل الإحداثيات على حجم الكف. بعدها المسافة من الرسغ للنقطة 9 بقت 1 دايمًا، سواء الإيد كبيرة أو صغيرة.

### الزوايا

```python
    a = world[[t[0] for t in ANGLE_TRIPLETS]]
    b = world[[t[1] for t in ANGLE_TRIPLETS]]
    c = world[[t[2] for t in ANGLE_TRIPLETS]]
    v1, v2 = a - b, c - b
```

- `[t[0] for t in ANGLE_TRIPLETS]`: list بأول نقطة من كل triplet (15 رقم). و `world[...]` بالـ list دي (fancy indexing) بيرجّع 15 نقطة مع بعض، شكلها `(15, 3)`.
- نفس الكلام لـ `b` (نقط المفاصل) و `c`.
- `v1 = a - b`: vector من المفصل للنقطة اللي قبله. `v2 = c - b`: vector من المفصل للنقطة اللي بعده. الـ 15 زاوية بتتحسب مع بعض من غير loop، وده أسرع بكتير.
- ملحوظة: الزوايا بتتحسب من `world` مش `rel`، والنتيجة واحدة لأن الزاوية مابتتغيرش بالإزاحة ولا بالتكبير.

```python
    cos = (v1 * v2).sum(1) / (np.linalg.norm(v1, axis=1) * np.linalg.norm(v2, axis=1) + 1e-12)
    angles = np.arccos(np.clip(cos, -1.0, 1.0)) / np.pi     # 0..1 (1 = straight finger)
```

- `(v1 * v2).sum(1)`: الـ dot product لكل صف: ضرب عنصر في عنصر وبعدين جمع على المحور 1 → 15 رقم.
- `np.linalg.norm(v1, axis=1)`: طول كل vector في `v1` (15 رقم)، ونفس الكلام لـ `v2`.
- القسمة = cos الزاوية (المعادلة تحت). الـ `1e-12` بيمنع القسمة على صفر.
- `np.clip(cos, -1.0, 1.0)`: بسبب أخطاء التقريب في الـ float، الـ cos ممكن يطلع `1.0000001`، و `arccos` لأي رقم بره [-1, 1] بيرجّع `NaN`. الـ clip بيمنع ده.
- `np.arccos(...)`: بيرجّع الزاوية بالـ radians من 0 لـ π.
- `/ np.pi`: بنحوّلها للمدى 0..1. التعليق بيوضح: `1` = زاوية 180° = الصباع مفرود على استقامته.

### مسافات الأطراف والتجميع

```python
    tips = world[TIPS]
    tip_dist = np.array([np.linalg.norm(tips[i] - tips[j]) for i, j in TIP_PAIRS]) / scale

    return np.concatenate([[1.0], rel.ravel(), angles, tip_dist])
```

- `tips = world[TIPS]`: الـ 5 أطراف، شكلهم `(5, 3)`.
- لكل زوج في `TIP_PAIRS` بنحسب المسافة بين الطرفين، وبنقسم على `scale` عشان المسافة تبقى "بالنسبة لحجم الكف" مش بالمتر. → 10 أرقام.
- `np.concatenate([...])`: بنلزق كل حاجة في vector واحد:
  - `[1.0]`: الـ flag إن الإيد موجودة.
  - `rel.ravel()`: `ravel` بتفرد الـ `(21, 3)` لـ 63 رقم: `[x0, y0, z0, x1, y1, z1, ...]`. (أول 3 أرقام دول بتوع الرسغ وهما دايمًا 0 بعد الطرح، يعني مابيضيفوش معلومة، بس وجودهم بيخلّي الترتيب بسيط: نقطة i في الأماكن من 3i لـ 3i+2.)
  - `angles`: 15 رقم.
  - `tip_dist`: 10 أرقام.
- المجموع 1 + 63 + 15 + 10 = 89 = `PER_HAND_SIZE`.

### الدالة الرئيسية `extract`: features كل إيد

```python
def extract(image_lm, world_lm, present, aspect=16 / 9):
    """Build the feature vector for one frame. aspect = frame width / height."""
    parts = []
    for slot in range(2):
        if present[slot]:
            parts.append(_hand_features(world_lm[slot]))
        else:
            parts.append(np.zeros(PER_HAND_SIZE))
```

- المدخلات هي نفس الصيغة الخام بتاعة `hands_to_arrays`، وده اللي بيخلّي نفس الدالة تشتغل على الداتا المتسجلة وعلى الكاميرا الحية.
- `aspect`: نسبة عرض الـ frame لطوله (1280/720 = 16/9). محتاجينها في الـ features بين الإيدين.
- `parts = []`: هنجمّع فيها 3 أجزاء ونلزقهم في الآخر.
- لكل slot: لو فيه إيد → نحسب الـ 89 feature. لو مافيش → 89 صفر (zero padding)، عشان الطول يفضل ثابت. والـ flag الأول هيبقى 0 فالموديل يعرف إن الجزء ده "فاضي".

### `extract`: الـ features بين الإيدين

```python
    inter = np.zeros(INTER_HAND_SIZE)

        pts = image_lm[:, :, :2] * np.array([aspect, 1.0])
```

- `inter = np.zeros(...)`: الافتراضي 28 صفر (لو فيه إيد واحدة أو مافيش).
- `if present[0] and present[1]`: بنحسبها بس لو الإيدين موجودين.
- هنا بنستخدم الـ **image** landmarks مش الـ world، لأن الـ world كل إيد ليها نقطة أصل خاصة بيها (نص الإيد نفسها)، فمانقدرش نقارن مكان إيد بالتانية. الـ image coords الاتنين في نفس "الإطار" (الصورة).
- `image_lm[:, :, :2]`: الإيدين، كل النقط، x و y بس → `(2, 21, 2)`.
- `* np.array([aspect, 1.0])`: التعليق بيشرح: x و y الاتنين من 0 لـ 1، بس الصورة عرضها أكبر من طولها، فبنمطّ x بنسبة العرض للطول عشان المسافات تبقى بنسب حقيقية (تفاصيل تحت).
- `palm`: متوسط حجم الكف (رسغ → قاعدة الوسطى) للإيدين، في نفس الوحدة. هنقسم عليه عشان المسافات ماتتأثرش بالبعد عن الكاميرا.

```python
        offset = (pts[1, 0] - pts[0, 0]) / palm
        cross = np.linalg.norm(pts[0, TIPS][:, None] - pts[1, TIPS][None], axis=2) / palm
```

- `offset`: الفرق بين رسغ الإيد التانية ورسغ الأولى (dx, dy)، مقسوم على حجم الكف → 2 أرقام. بيقول الإيدين بعاد عن بعض قد إيه وفي أنهي اتجاه.
- `cross`: مسافة كل طرف صباع في الإيد الأولى من كل طرف في التانية:
  - `pts[0, TIPS]` شكله `(5, 2)`، و `[:, None]` بتخليه `(5, 1, 2)`.
  - `pts[1, TIPS][None]` شكله `(1, 5, 2)`.

  - `np.linalg.norm(..., axis=2)` بيحسب الطول → `(5, 5)` = 25 مسافة.
- ده مهم جدًا لـ gesture زي `clone_seal` (الصوابع متقاطعة) لأن المسافة بين سبابة إيد وسبابة التانية بتبقى صغيرة جدًا.
- `inter = np.concatenate([[1.0], offset, cross.ravel()])`: flag + 2 + 25 = 28.
- `parts.append(inter)`: الجزء التالت.

### الـ mirror (data augmentation)

```python
def mirror(image_lm, world_lm, present):
    """Left/right mirror of a frame (data augmentation): a left-hand sample becomes a right-hand one."""
    image_lm, world_lm = image_lm.copy(), world_lm.copy()
    image_lm[..., 0] = np.where(present[:, None] > 0, 1.0 - image_lm[..., 0], 0.0)
    world_lm[..., 0] = -world_lm[..., 0]
    return order_slots(image_lm, world_lm, present.copy())
```

- الـ docstring: بنعكس الـ frame يمين-شمال، فعيّنة متسجلة بالإيد الشمال تبقى كأنها بالإيد اليمين. ده بيستخدمه `train.py` عشان يضاعف الداتا.
- `.copy()`: عشان مانعدلش الـ arrays الأصلية (اللي هتتستخدم برضه في التدريب كما هي).
- `image_lm[..., 0]`: الـ `...` معناها "كل المحاور اللي قبل"، فده x بتاع كل النقط في الإيدين، شكله `(2, 21)`.
- `1.0 - x`: عكس x في الصورة (0..1)؛ 0.2 بتبقى 0.8.
- `np.where(present[:, None] > 0, ..., 0.0)`: بنعمل العكس **بس للإيد الموجودة**. الإيد الغايبة أصفار، و `1 - 0 = 1` كان هيحوّل الأصفار لـ 1 ويبوّظ الـ padding. `present[:, None]` شكله `(2, 1)` عشان يتطابق مع `(2, 21)`.
- `world_lm[..., 0] = -world_lm[..., 0]`: في الـ world الأصل عند نص الإيد، فالعكس = تغيير إشارة x. (الأصفار بتفضل أصفار.)
- `order_slots(...)`: بعد العكس، الإيد اللي كانت على الشمال بقت على اليمين، فلازم نعيد الترتيب بنفس قاعدة `HandTracker`.

### ترتيب الـ slots: `order_slots`

```python
def order_slots(image_lm, world_lm, present):
    """Put present hands first, sorted left-to-right by wrist x (same rule as HandTracker)."""
    keys = [(0 if present[s] else 1, image_lm[s, 0, 0]) for s in range(2)]
    order = sorted(range(2), key=lambda s: keys[s])
    return image_lm[order], world_lm[order], present[order]
```

- الـ docstring: الإيد الموجودة الأول، وبعدين ترتيب من الشمال لليمين بـ x الرسغ (نفس قاعدة `HandTracker` بالظبط).
- `keys`: لكل slot بنعمل tuple من حاجتين: `0` لو موجود و `1` لو لأ، وبعدين x الرسغ `image_lm[s, 0, 0]` (slot s، نقطة 0، محور x). Python بيقارن الـ tuples عنصر عنصر، فالموجود دايمًا قبل الغايب، ولو الاتنين موجودين الأصغر x الأول.
- `sorted(range(2), key=...)`: بيرجّع ترتيب الـ slots، مثلًا `[1, 0]` يعني "بدّل".
- `image_lm[order]`: NumPy بيعيد ترتيب المحور الأول حسب الـ list، ونفس الكلام للاتنين التانيين.

## 3. مفاهيم مهمة

### أ) ليه features ومش الإحداثيات الخام؟

لو ادّينا الموديل الـ landmarks زي ما هي، هيتعلم حاجات غلط:

| المشكلة | مثال | الحل في الكود |
|---|---|---|
| مكان الإيد في الصورة | نفس الـ rasengan على شمال الشاشة ويمينها أرقام مختلفة تمامًا | طرح الرسغ (`world - world[0]`) |
| بُعد الإيد عن الكاميرا / حجم الإيد | إيد طفل وإيد راجل، أو قريبة وبعيدة | القسمة على حجم الكف (`/ scale`) |
| الشكل مش واضح من الأرقام | "الصباع مثني" محتاج الموديل يستنتجه من 9 أرقام | الزوايا مباشرة |
| العلاقة بين الصوابع | الـ OK-ring في `fire` = الإبهام لازق في السبابة | `tip_dist` |

الـ features بتحط "المعرفة اللي إحنا عارفينها" جاهزة للموديل، فبيتعلم بداتا أقل ويعمّم أحسن.

### ب) الثبات للإزاحة والحجم (translation & scale invariance)

```
قبل:  rasengan عند (0.20, 0.50)      نفس الـ rasengan عند (0.70, 0.40)، أقرب للكاميرا
       نقطة 9 = (0.20, 0.42)           نقطة 9 = (0.70, 0.28)
                     │                                 │
            − الرسغ  ▼                        − الرسغ  ▼
       rel[9] = (0, -0.08)              rel[9] = (0, -0.12)
                     │                                 │
            ÷ 0.08   ▼                        ÷ 0.12   ▼
       rel[9] = (0, -1.0)               rel[9] = (0, -1.0)    ← نفس الأرقام
```

(المثال بالـ image coords للتبسيط؛ الكود بيعمل نفس الحركة على الـ world coords.)

**ملاحظة:** الـ features **مش** ثابتة للدوران (rotation)، وده مقصود: اتجاه الإيد جزء من الـ gesture (مثلًا كف مفتوح ناحية الكاميرا ≠ كف لفوق).

### ج) الزاوية بالـ dot product و arccos

لنقطة مفصل `b` ونقطتين حواليه `a` و `c`:

```
v1 = a − b        v2 = c − b

              v1 · v2
cos θ  =  ─────────────────        θ = arccos(cos θ)  ∈ [0, π]
           |v1| × |v2|

feature = θ / π   ∈ [0, 1]
```

أمثلة (2D للتبسيط، b = (1, 0)):

| a | c | v1 | v2 | cos θ | θ | feature | المعنى |
|---|---|---|---|---|---|---|---|
| (0,0) | (2,0) | (-1,0) | (1,0) | -1 | 180° | **1.0** | صباع مفرود |
| (0,0) | (1,1) | (-1,0) | (0,1) | 0 | 90° | **0.5** | مثني نص ثنية |
| (0,0) | (0.3,0.1) | (-1,0) | (-0.7,0.1) | ≈0.99 | ≈8° | **≈0.05** | مقفول خالص |

الزوايا بطبيعتها مابتتأثرش بالمكان ولا الحجم، فهي أنضف feature لشكل الصوابع.

### د) الـ 10 أزواج أطراف

```
         إبهام  سبابة  وسطى  بنصر  خنصر
إبهام      -     (0,1)  (0,2)  (0,3)  (0,4)
سبابة             -     (1,2)  (1,3)  (1,4)
وسطى                     -     (2,3)  (2,4)
بنصر                            -     (3,4)
خنصر                                   -
```

مثال: في `fire` (OK-ring) المسافة `(0,1)` إبهام-سبابة صغيرة جدًا. في `rasengan` (صوابع مفرودة ومفتوحة) كل المسافات كبيرة. في `chidori` (claw) المسافات متوسطة.

### هـ) الـ features بين الإيدين وتصحيح الـ aspect ratio

الـ image coords normalized: x مقسوم على العرض (1280) و y مقسوم على الطول (720). يعني "0.1 في x" = 128 بكسل، لكن "0.1 في y" = 72 بكسل بس. لو حسبنا مسافة على طول، المسافات الأفقية هتبان أصغر من حقيقتها.

```
بعد الضرب في [16/9, 1]:   x من 0 لـ 1.78 ، y من 0 لـ 1   → وحدة واحدة = طول الصورة
0.1 × 1.78 = 0.178 وحدة = 128 بكسل      0.1 وحدة في y = 72 بكسل    ← نفس النسبة ✓
```

وعشان كده `aspect` بيتحفظ في الـ meta بتاع كل session في `collect_data.py`، وفي التشغيل بنبعت `w / h` الحقيقي.

### و) الـ presence flags والـ zero padding

الموديلات في scikit-learn لازم كل sample يبقى نفس الطول. لكن عدد الإيدين بيتغير (0، 1، 2). الحل:

```
إيد واحدة:   [1, ...89 feature...] [0, 0, 0, ... 89 صفر] [0, ... 28 صفر]
إيدين:       [1, ...89 feature...] [1, ...89 feature...] [1, offset, 25 مسافة]
```

الـ flag (1 أو 0) بيقول للموديل صراحةً "الجزء ده حقيقي ولا padding"، عشان مايفهمش الأصفار على إنها إحداثيات حقيقية.

### ز) خريطة الـ 206 رقم

| الـ indices | الجزء | العدد |
|---|---|---|
| 0 | slot 0: flag | 1 |
| 1–63 | slot 0: إحداثيات نسبية (21×3) | 63 |
| 64–78 | slot 0: زوايا | 15 |
| 79–88 | slot 0: مسافات الأطراف | 10 |
| 89 | slot 1: flag | 1 |
| 90–152 | slot 1: إحداثيات نسبية | 63 |
| 153–167 | slot 1: زوايا | 15 |
| 168–177 | slot 1: مسافات الأطراف | 10 |
| 178 | بين الإيدين: flag | 1 |
| 179–180 | فرق مكان الرسغين (dx, dy) | 2 |
| 181–205 | مسافات الأطراف 5×5 | 25 |
| | **المجموع** | **206** |

```
per hand  = 1 + 63 + 15 + 10 = 89
inter     = 1 +  2 + 25      = 28
total     = 2 × 89 + 28      = 206
```

### ح) `FEATURE_VERSION` بيحمينا من إيه؟

الموديل المتدرب بيتعلم "الرقم رقم 64 = زاوية قاعدة الإبهام". لو غيّرنا `features.py` (مثلًا ضفنا feature) من غير ما نعيد التدريب، الموديل القديم هيقرا أرقام في أماكن غلط ويدّي نتايج غلط تمامًا **من غير أي error**. الحل:

- `train.py` بيحفظ `"feature_version": FEATURE_VERSION` جوه ملف الموديل.
- `classifier.py` وهو بيحمّل الموديل بيقارن، ولو مختلفين بيطلع رسالة واضحة: `Re-run train.py`.

وبما إن `collect_data.py` بيحفظ الـ landmarks الخام مش الـ features، إعادة التدريب مش محتاجة نسجّل الداتا من الأول.

### ط) الـ mirror augmentation و `order_slots`

`train.py` بيعمل لكل frame 3 نسخ: الأصلي، والمعكوس (`mirror`)، ونسخة فيها noise صغير (jitter). المعكوس معناه إن لو سجّلنا الـ rasengan بالإيد اليمين بس، الموديل هيعرفه بالإيد الشمال كمان.

ليه `order_slots` ضروري بعد العكس؟

```
قبل العكس:   slot 0 = إيد عند x=0.3      slot 1 = إيد عند x=0.6
بعد 1 − x:    slot 0 = إيد عند x=0.7      slot 1 = إيد عند x=0.4    ← الترتيب بقى غلط!
order_slots:  slot 0 = إيد عند x=0.4      slot 1 = إيد عند x=0.7    ← رجع زي HandTracker ✓
```

لو مارتبناش، الداتا المعكوسة هتبقى بترتيب عمر `HandTracker` ما هيطلعه في التشغيل الحقيقي.

## 4. لو غيّرنا ... هيحصل إيه؟

1. **لو شلنا القسمة على `scale`:** نفس الـ gesture قريب من الكاميرا وبعيد عنها هيدّي أرقام مختلفة في الـ 63 إحداثية والـ 10 مسافات، فالموديل هيحتاج داتا أكتر بكتير على كل المسافات، وهيغلط لما نقف على مسافة ماتسجلتش.
2. **لو غيّرنا حاجة في `features.py` من غير ما نزوّد `FEATURE_VERSION`:** البرنامج هيشتغل عادي من غير error، بس الموديل القديم هيدّي توقعات غلط لأن الأرقام اتغير معناها. لو زوّدناه، `classifier.py` هيرفض الموديل القديم ويطلب `train.py`.
3. **لو شلنا `np.clip`:** معظم الوقت مافيش مشكلة، لكن مرة كل فين وفين صباع مفرود تمامًا هيطلع cos = `1.0000001`، و `arccos` يرجّع `NaN`، و `NaN` ده ممكن يبوّظ التوقع أو التدريب.
4. **لو شلنا تصحيح الـ `aspect`:** المسافات الأفقية بين الإيدين هتتحسب أصغر من الرأسية، فالـ features بين الإيدين هتتغير لما الإيدين يتحركوا أفقيًا مقابل رأسيًا، وده هيأثر على `clone_seal`.
5. **لو نسينا `order_slots` في `mirror`:** نص الداتا المعكوسة اللي فيها إيدين هتبقى بترتيب الـ slots معكوس عن الحقيقة، فالموديل هيتعلم أنماط مش هتظهر في التشغيل، وغالبًا دقة `clone_seal` هتقل.
6. **لو استخدمنا `image_lm` بدل `world_lm` في `_hand_features`:** الـ features هتتأثر بالـ perspective وبالـ aspect ratio (x و y مش بنفس الوحدة)، وعمق z هيبقى أضعف بكتير. الموديل هيشتغل بس هيبقى أقل ثباتًا لما الإيد تلف.
